# Тестовый и рабочий бот

## Ветки и запуск

- `main` — рабочий код. Существующие расписания публикуют в основной канал.
- `develop` — новые функции. После проверки переносим код через PR develop → main.
- **Test bot in private channel** — ручной тест. В Actions выбирайте **main**:
  workflow берёт код src/tests/config из develop и записывает SHA в Summary.
  Main остаётся веткой хранения состояния; тестовый код в main не коммитится.
- Запуск этого Action из develop запрещён. Рабочие Actions также работают только из main.
- Тестовый канал не запускается по расписанию и не вызывается при push/PR.

## Подключение приватного канала

1. Добавьте бота администратором канала с правом публикации сообщений.
2. В Settings → Secrets and variables → Actions → New repository secret добавьте:
   - `TEST_TELEGRAM_BOT_TOKEN` — токен тестового бота. Можно использовать токен
     текущего бота, если он добавлен в оба канала.
   - `TEST_TELEGRAM_CHANNEL_ID` — числовой ID приватного канала вида -100….
3. Рабочие TELEGRAM_BOT_TOKEN и TELEGRAM_CHANNEL_ID оставьте без изменения.
   Секреты не нужно присылать в чат или помещать в файлы.
4. Actions → Test bot in private channel → Run workflow → main.
   Сначала выберите check_connection: проверка каналов без публикации и платных API.
   Затем collect_and_publish для полного теста. Также доступны collect, publish, retro.
5. Проверьте результат в приватном канале и Bot result в Summary.
   NO POST означает, что подходящий проверенный пост не получен, а не успешную публикацию.
6. После проверки создайте PR develop → main, дождитесь Bot tests и примените PR.
   Не переносите тестовые черновики или историю в рабочее хранилище.
   Новые изменения develop нужно снова проверить до переноса.

До платных вызовов проверяется, что тестовый канал приватный и отличается от рабочего.
Без тестовых секретов запуск остановится без публикации. Сами изменения инфраструктуры
не отправляют сообщения. Доступ к GitHub-секретам настраивается отдельно от Telegram.

## Состояние и расходы

Рабочее состояние: storage/dubai_news. Тестовое: storage/dubai_news_staging.
Очереди, история, дедупликация, кеш поиска и недельные лимиты ретрорубрики раздельные.
Приватные ID назначения удаляются из тестовой истории перед коммитом.
Репозиторий публичный: содержание тестовых постов и отчёты сохраняются в нём,
поэтому приватный канал здесь предназначен для проверки публичного новостного контента.

OpenAI использует один неизменяемый при переключении окружений журнал
storage/dubai_news/openai_budget.json. Общий предел — $3/месяц для обоих запусков.
Тесты могут израсходовать часть общего дневного лимита; ручной обход не отменяет
месячный предел. Одинаковая concurrency-группа исключает одновременную запись.
DeepSeek отключён в новой версии develop. Оплата Serper отдельная; запуск retro может сделать запрос Serper.

Это разделение каналов и данных для доверенного кода, а не изоляция от злонамеренного
кода: пользователи с правом изменять workflows могут обращаться к repository secrets.
Проверяйте PR до добавления непроверенного кода в develop.
