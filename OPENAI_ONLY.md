# Подготовка постов без DeepSeek

Новая версия проверяется в develop. Схема:
поиск OpenAI → полный текст источника → GPT-4.1 mini (отбор + пост одним запросом)
→ отдельная проверка фактов GPT-4.1 mini → Telegram.

- Все сетевые обращения к DeepSeek удалены, включая ретрорубрику и старый fallback проверки.
- Редактор и автор объединены в один запрос. Локальные проверки URL, текста и дублей сохранены.
- Не более двух попыток подготовки кандидатов за запуск; отдельная проверка обязательна.
- Один запрос без автоматических повторов. Результат кешируется на 7 дней.
  Незавершённая или ошибочная попытка для тех же входных данных тоже не повторяется автоматически.
- 1000 выходных токенов на подготовку; вход ограничен консервативным пределом стоимости.
- Каждый вызов заранее резервируется в общем журнале OpenAI. Запись попытки генерации
  сохраняется до сетевого запроса, чтобы сбой не вызвал повторную оплату при следующем запуске.
- Поиск, генерация и проверка вместе ограничены $3/месяц. История расходов не сбрасывается.
  Генерация оставляет бюджет для проверки; обход дневного лимита не отменяет месячный.
- Дневной предел 8 текстовых вызовов включает генерацию и проверку, поиск ограничен отдельно.
- Счётчик writer_calls показывает попытки подготовки кандидатов; openai_calls — фактические вызовы.
- OpenAI-счёт может показывать меньше резерва: резерв консервативный, а не фактическая стоимость.

Модель зафиксирована: gpt-4.1-mini-2025-04-14.
Документация модели: https://developers.openai.com/api/docs/models/gpt-4.1-mini

## Проверка и перенос

Запустите Test bot in private channel → main → collect_and_publish.
Refresh search выключен, чтобы использовать сохранённую подборку.
Проверьте пост в приватном канале. Затем переносите develop → main через PR.
До переноса основной канал продолжает работать на прежней версии main.
Тестовый workflow из main ещё может передавать старый секрет DeepSeek в окружение,
но новый код его не читает и не использует. После переноса удаляется и эта настройка.
