# OpenAI: отдельный проверяющий с бюджетом до $3 в месяц

DeepSeek остаётся для первичного отбора и подготовки русского текста. OpenAI
проверяет готовый пост по исходнику и выполняет резервный поиск новостей. Модель зафиксирована:
`gpt-4.1-mini-2025-04-14`. Новых Python-зависимостей нет.

## Подключить

1. Создать API-ключ в https://platform.openai.com/api-keys с доступом к модели.
2. Открыть https://github.com/AlAlNi/dubai-news-bot/settings/secrets/actions
   → **New repository secret**.
3. Имя: `OPENAI_API_KEY`; значение: созданный ключ.
4. После применения этого изменения очередной сбор автоматически выберет OpenAI.
   `DEEPSEEK_API_KEY` по-прежнему нужен для отбора и написания постов.

Ключ не помещать в код, `.env` в репозитории, Issues или логи. Пока секрет не задан,
сохраняется предыдущая проверка через DeepSeek. При наличии ключа ошибки OpenAI
не приводят к переключению на DeepSeek: сомнительный пост не публикуется.
Ранее подготовленные DeepSeek-черновики в режиме OpenAI пропускаются; нужен
новый сбор. Публикация не получает значение OpenAI-ключа, только имя проверяющего.

## Ограничения расходов

| Механизм | Значение |
|---|---|
| Месячный предел резервирования, UTC | $3 |
| Проверок в сутки, UTC | Не более 8 |
| Поисковых вызовов в сутки, UTC | Не более 2; кеш на половину суток |
| Ответ | До 1 600 токенов проверки; до 1 000 токенов поиска |
| Вход проверки | UTF-8 размер всего JSON + 1 024 байта запаса ≤ 20 000 |
| Вход поискового запроса | UTF-8 размер всего JSON + 1 024 байта запаса ≤ 8 000 |
| Резерв на попытку проверки / поиска | $0,01056 / $0,025 |
| Повторы HTTP-запроса | Отключены |
| Кеш идентичных входа, поста, промпта и модели | 7 дней, до 500 записей |

Цена GPT-4.1 mini на 15.09.2026: $0,40 за миллион входных и $1,60 за миллион
выходных токенов. Для резерва вход консервативно принимается за 20 000 токенов;
выход — за 1 600. Резерв списывается до HTTP-запроса и не возвращается даже при
ошибке/таймауте. Это намеренно завышенная оценка, а не сумма счёта OpenAI.
При 8 проверках в день за 31 день резерв только проверок составляет $2,61888.
Поиск расходует тот же месячный предел $3: суммарные максимумы всех операций
не гарантируются, после исчерпания общего резерва платные операции останавливаются.
Учет фактически возвращённых `usage`
токенов и оценка их стоимости ведутся отдельно, без предположения о скидке кеша.

Пример: 2 000 входных + 500 выходных токенов стоят около $0,0016 за проверку;
это пример расчёта, не прогноз расхода. Отказы тоже могут оплачиваться.
Ограничения относятся только к запросам этого бота и указанным тарифам,
не к другим приложениям с тем же ключом, DeepSeek, налогам или всем расходам аккаунта.

Через **Settings → Secrets and variables → Actions → Variables** можно уменьшить:

- `OPENAI_MONTHLY_BUDGET_USD` (от 0 до 3, по умолчанию 3);
- `OPENAI_MAX_CALLS_PER_DAY` (от 0 до 8, по умолчанию 8).
- `OPENAI_MAX_SEARCHES_PER_DAY` (от 0 до 2, по умолчанию 2).

`OPENAI_NEWS_SEARCH_ENABLED=false` отключает только резервный поиск. По умолчанию
он включён и использует тот же `OPENAI_API_KEY`.

Нулевой предел останавливает новые платные проверки; существующий кеш доступен.
Попытка задать больший/некорректный предел блокирует новые запросы.
Модель нельзя поменять переменной окружения: сначала требуется пересмотреть тариф
и ограничения в коде. Исчерпание лимита приостанавливает сбор до следующего
периода; уже проверенные готовые посты могут публиковаться.

## Надёжность учёта

`storage/dubai_news/openai_budget.json` содержит только месяцы, дни, счётчики,
резервы и агрегированные токены. Не удалять и не обнулять этот файл в текущем
месяце. При его отсутствии/повреждении запросы блокируются.

Все три workflow используют `concurrency: dubai-news-storage`, не отменяют
работающий запуск и получают актуальную `main`. Перед КАЖДЫМ платным запросом
сборщик записывает резерв и делает отдельный commit/push только бюджетного файла.
Если push не удался, запрос не отправляется. Поэтому аварийное завершение или
сбой финального коммита не теряет уже выделенный резерв. Финальный шаг сохраняет
usage и кеш даже при ошибке сборщика. Принудительно переписывать историю `main`
или запускать старые версии параллельно нельзя: это нарушает общий учёт.

Вне GitHub Actions действует только локальный файл и блокировка. Не запускать
несколько независимых копий с одним ключом: их бюджеты не суммируются автоматически.
Для локальной разработки `SOURCE_VERIFIER=deepseek` оставляет прежний путь;
`SOURCE_VERIFIER=openai` требует OpenAI-ключ без автоматического отката.

В отчёте сбора: `openai_calls`, `openai_cache_hits`, `verification_paused`.
`openai_calls` теперь включает поисковые запросы; отдельно доступны
`openai_search_calls` и `openai_search_cache_hits`.
Окончательный расход проверяется в https://platform.openai.com/usage.
Сверка проверяет соответствие полученному описанию RSS/GNews, а не истинность СМИ.

## Резервный поиск

Поиск вызывается только после неуспеха RSS/GNews/Google News RSS, если в очереди
меньше двух проверенных постов и проверка не остановлена из-за бюджета/ошибки.
Один запрос Responses API принудительно использует `web_search`, с
`max_tool_calls=1`, `search_context_size=low`, без автоматических повторов.
Кеш ссылок действует в пределах половины суток UTC, включая пустые результаты.
Ошибки API могут повториться в следующем запуске, но также занимают суточный лимит.

Поиск ограничен доменами Dubai Media Office, RTA, Dubai Police, DEWA,
Dubai Airports, Emirates, Gulf News, Khaleej Times, The National,
Arabian Business и Gulf Business. Берётся до пяти URL из аннотаций/источников
поискового инструмента, а не из произвольного текста ответа модели.

Бот сам загружает HTML каждой статьи, извлекает исходный заголовок, текст и
дату публикации. Статьи старше 48 часов, без подтверждаемой даты, слишком
короткие, недоступные и перенаправляющие за пределы списка доменов пропускаются.
Текст извлекается из Article/NewsArticle JSON-LD или размеченного тела статьи.
Для Dubai Media Office относительная дата в `banner-i-rel` сверяется с датой
адреса новости; сохраняется начало подтверждённого дня по времени Дубая.
Неопределённые/противоречивые даты не восстанавливаются моделью. Поддержка сайта
зависит от доступности HTML и его разметки; универсальный парсер не гарантируется.

Найденная статья проходит прежний отбор, перевод, проверку цитат и антидубликаты.
В черновике сохраняются `source_published_at`, `source_retrieved_at` и исходный URL.
Текст поисковой модели никогда не используется как подтверждение фактов.

В едином ledger добавляется `search_calls` без обнуления старых записей v1.
Для поиска резервируется $0,025 с учётом одного платного инструмента ($0,01),
фиксированного блока поискового контекста 8 000 входных токенов и запаса на
вход/выход модели. До покупки поиска проверяется остаток ещё минимум на одну
проверку поста. Резерв сохраняется в GitHub до запроса, как и для проверяющего.
При учёте `usage` стоимость поискового контекста добавляется консервативно,
даже если API уже включило его в возвращённые входные токены: оценка может быть
завышена, окончательный расход виден в OpenAI Usage.

## Проверка

В ручном запуске обоих сборщиков (`Run workflow`, ветка `main`) есть галочка
«Обойти дневной лимит OpenAI (бюджет $3/месяц сохраняется)». По умолчанию выключена.
Она обходит дневные ограничения поиска и проверки постов только для этого ручного
запуска; расписание её игнорирует. Месячный бюджет, резервирование до запроса,
проверка источников, кеш и максимум один запрос поиска за запуск сохраняются.
Ручные расходы записываются в тот же журнал и учитываются в последующих запусках.
Галочка не принуждает поиск: он по-прежнему включается при нехватке готовых новостей.

`python -m pytest tests -q`

API подменяются в тестах; проверяются сохранение лимитов между экземплярами,
смена суток/месяца, отказ при повреждении состояния и ошибке push, отсутствие
повторов/отката, кеш, размер запроса, JSON-ответы и отбор черновиков по проверяющему.
Качество модели оценивается отдельно на реальных парах «исходник — пост».
